# Map reference layers

The interactive map (`UsShopMap`) draws highways, county lines, built-up areas,
water and town names underneath its shop markers. This is how that data is
produced.

## Why it exists

Zoomed out, the map is a choropleth and works fine. Zoomed into a state it used
to be a pale field with a handful of dots on it — nothing on screen was a
*place*, so there was no way to judge where a shop actually was or how far it
was from anywhere else. These are the layers a real basemap draws at that
scale, cut down to the few that carry orientation.

Measured against live vector tiles over Denver, a commercial basemap at metro
zoom shows roughly 114 road lines, 300 road labels, 70 water polygons, 66 place
labels and one county boundary. That is the gap these files close.

## Why the files are committed rather than generated at build time

The sources total ~60 MB of shapefiles and take several minutes to process. The
output is deterministic and only changes when the source datasets do, so it is
generated by hand and checked in. Nothing in `scripts/` runs during `next
build` or at request time.

## Why per state rather than one national file

`/api/directory/map` is what the homepage downloads on scroll, and it is 62 KB
brotli. County boundaries nationally add ~89 KB, interstates ~19–39 KB and
water ~18 KB — roughly a 3× regression on the most-visited page, to serve a
view most visitors never open.

Per state, fetched on click, the same layers cost a median ~18 KB gzipped
(worst case New York at ~56 KB). The national payload is unchanged.

## Projection

Everything is projected with the **same** `geoAlbersUsa().scale(1300)
.translate([487.5, 305])` instance the shop points use in
`src/lib/directory/usmap.ts`. If that ever changes, these files must be
regenerated or roads will sit beside shops instead of underneath them.

Coordinates are emitted at one decimal place (`geoPath().digits(1)`); full
precision costs about 4× the bytes for detail no one can see at this scale.

## Sources

All public domain, no API key, no attribution required.

| Layer | Source | Notes |
|---|---|---|
| Interstates, US highways | Census TIGER 2024 `PRIMARYROADS` | filtered to `RTTYP` I and U, dissolved by route name, segments under 3 km dropped so ramps and carriageway splits don't triple the weight |
| County boundaries | `us-atlas/counties-10m.json` | already a dependency; emitted as a single `topojson.mesh` so it's one DOM node |
| Built-up areas | Natural Earth 10m urban areas | |
| Lakes, rivers | Natural Earth 10m lakes (`scalerank <= 4`) and river centerlines | |
| Town names | Census GENZ2023 place boundaries, per state | `ALAND > 15 km²`, centroids only |
| Town population | Natural Earth 10m populated places | ranks the ~770 places that have a figure; land area ranks the rest |

Population matters more than it sounds: ranked by land area alone, Aurora sorts
above Denver, and a merged Front Range cluster came out labelled "Aurora area".

## Regenerating

```sh
mkdir geo && cd geo && npm i mapshaper d3-geo topojson-client
cp <repo>/scripts/map-layers/{build.mjs,places.mjs,fips.json} .

curl -sSLO https://www2.census.gov/geo/tiger/TIGER2024/PRIMARYROADS/tl_2024_us_primaryroads.zip
curl -sSLO https://naciscdn.org/naturalearth/10m/cultural/ne_10m_urban_areas.zip
curl -sSLO https://naciscdn.org/naturalearth/10m/physical/ne_10m_lakes.zip
curl -sSLO https://naciscdn.org/naturalearth/10m/physical/ne_10m_rivers_lake_centerlines.zip
curl -sSLO https://naciscdn.org/naturalearth/10m/cultural/ne_10m_populated_places_simple.zip
mkdir places && for f in 01 02 04 ... 56; do
  curl -sSLf -o "places/p$f.zip" \
    "https://www2.census.gov/geo/tiger/GENZ2023/shp/cb_2023_${f}_place_500k.zip"
done
for z in *.zip; do unzip -oq "$z"; done

npx mapshaper tl_2024_us_primaryroads.shp \
  -filter 'RTTYP=="I"||RTTYP=="U"' -each 'this.properties={n:FULLNAME,t:RTTYP}' \
  -dissolve n,t -simplify 4% keep-shapes -filter 'this.length > 3000' \
  -o precision=0.0005 format=geojson roads.json
npx mapshaper ne_10m_urban_areas.shp -each 'this.properties={}' \
  -simplify 12% keep-shapes -o precision=0.001 format=geojson urban.json
npx mapshaper ne_10m_lakes.shp -filter 'scalerank<=4' -each 'this.properties={}' \
  -simplify 12% keep-shapes -o precision=0.001 format=geojson lakes.json
npx mapshaper ne_10m_rivers_lake_centerlines.shp -each 'this.properties={}' \
  -simplify 12% keep-shapes -o precision=0.001 format=geojson rivers.json
npx mapshaper ne_10m_populated_places_simple.shp \
  -filter 'adm0name=="United States of America"' \
  -each 'this.properties={n:name,p:pop_max,s:adm1name}' -o format=geojson pop.json

node build.mjs  <repo>/src/data/map-layers   # roads, counties, water, urban, shields
node places.mjs <repo>/src/data/map-layers   # town names — must run second
```

`places.mjs` reads the files `build.mjs` wrote and adds the `places` array, so
the order matters.
